# MANOR WALK 3D

「バイオハザードみたいな固定カメラで、3Dキャラに空間を歩かせてみたい」という
ご相談から生まれたオリジナル作品です。キャラクター・ストーリー・グラフィック・
タイトルは元のゲームとは一切関係のない、この演出手法にインスパイアされた
オリジナルの内容にしています。

古い洋館(玄関ホール・廊下・書庫・書斎の4部屋)を歩き回り、最奥の光る扉に
たどり着くのが目的です。Three.js製、部屋ごとに切り替わる固定カメラ+
タンク操作(その場旋回+前進/後退)という、初代サバイバルホラー系ゲームの
操作感を再現した探索デモです。

## 遊び方

`index.html` をブラウザで開くか、ローカルサーバーで配信してください。

```bash
cd games/manor-walk-3d
python3 -m http.server 8080
# http://localhost:8080 を開く
```

- **▲/▼** で前進・後退(向いている方向を基準に移動する、いわゆるタンク操作)
- **◀/▶** でその場旋回
- カメラはキャラクターを追従せず、部屋ごとに固定された視点が瞬時に
  切り替わる(=「カット」)。画面左上に現在の部屋名を表示している
- 廊下の途中で左に曲がると書庫に寄り道できる(必須ではない)
- 書斎の奥にある光る扉にたどり着くとゴール

## 仕組みメモ

判定ロジックは`manor.js`にDOM/Three.js非依存の純粋関数としてまとめている
(Node上で直接ユニットテスト可能)。

- 4部屋(玄関ホール・廊下・書庫・書斎)をそれぞれ1つの矩形(X/Z平面)として
  定義し、隣接する部屋は「共有する境界線の一部を出入口の幅として重ねる」
  形で接続している(例: 廊下の幅がそのまま玄関ホール北壁の開口部になる)。
  壁メッシュ側はこの矩形データを見ながら、出入口の範囲だけ壁を
  切り欠いて手動で配置している
- 衝突判定(`canStandAt`)は各部屋の矩形を`WALL_MARGIN`分だけ外側に
  膨らませたものの和集合として実装し、キャラクターを点として扱う。
  出入口をまたぐ移動は、隣接する2部屋の膨らませた矩形が出入口の範囲で
  必ず重なるようにデータを作ることで、境界線上での誤判定(見た目上は
  通路なのに壁判定になる)を避けている
- 移動(`resolveMove`)は軸ごとに分離して衝突判定するため、壁に対して
  斜めに歩いても引っかからず、壁に沿って滑るように移動できる
- カメラの部屋判定(`zoneAt`)も衝突判定と同じ膨らませた矩形を使っている。
  開発中、`zoneAt`だけ膨らませる前の矩形を使っていたため、壁にぴったり
  張り付いて立っている(=衝突判定上は許可されている)位置で
  どの部屋にも属さない扱いになり、無関係な部屋の固定カメラに
  切り替わってしまうバグがあった。衝突判定と部屋判定で同じ矩形定義を
  使うよう統一して修正した
- 各部屋の固定カメラは、部屋の中(天井より低い高さ)に手動で位置と
  注視点を置く形で用意した。最初は部屋の外や近くの家具の目の前に
  カメラを置いてしまい、画面が壁や家具でほぼ覆われて何も見えなくなる
  失敗を何度かしたため、実際にキャラクターを各部屋の代表位置に置いて
  スクリーンショットを撮りながら位置を調整した
- キャラクターは他のThree.js製ゲームと同じく、プリミティブ形状のみで
  組んだプロシージャルな人型モデル(外部アセット不使用)

## テスト

- `manor.js`の純粋関数をNode上で直接ユニットテスト(各部屋の内外判定・
  出入口をまたいだ移動可能性・壁での衝突/スライド・部屋判定・
  ゴール判定・タンク操作の前進/後退/旋回の積分)
- Playwrightで実際にゲームをプレイし、スタート→十字ボタンの実タップ
  (押し続けでの前進/後退/旋回)→玄関ホール→廊下→書斎という
  室内移動でカメラが自動的に切り替わること、廊下で曲がって書庫に
  到達できること、壁に向かって歩いても擦り抜けないこと、書斎奥の
  扉に到達するとゴール画面が出ることを検証
- 4つの固定カメラそれぞれについて、キャラクターがその部屋の代表位置に
  いる状態のスクリーンショットを撮り、キャラクターが画面内に収まって
  いるか・壁や家具でカメラが塞がれていないかを目視で確認・調整
- `window.__debug`フックは最終コミット前に削除済み(`grep -n "__debug"`
  で該当なしを確認)
