# THIRD PERSON BOXER 3D

「参照写真(グリッド地面の上でガードを構える3Dキャラクターを背後から
見下ろすカメラ)と同じ構図を、画像を背景に貼るのではなく、実際の3D
モデル・3D地面・3Dカメラで再現してほしい」という依頼から始まった
プロジェクトです。最初のバージョンではカメラ位置と空間構成のみを
再現し、続けて「左右スワイプで素早く回避移動する操作感を試したい」
という依頼でスワイプ操作(左右移動)を追加、さらに「回避時に姿勢も
変化させてほしい(上半身を傾け、腰を落とし、膝を曲げる、格闘ゲームの
ような紙一重の回避動作)」という依頼で回避姿勢のアニメーションを
追加しました。

スマートフォン縦画面専用の試作です(PC操作は想定していません)。
攻撃・敵・HP・ダメージ・アニメーション・エフェクト・UI・サウンド・
ゲームルールなど、依頼されていない要素は追加していません。

Three.js製、キャラクターは(既存の`counter-punch-3d`と同様に)素の
プリミティブ形状で構築しています。タイトル・キャラクターデザインは
参照写真とは無関係の完全オリジナルです。

## 遊び方

`index.html` をブラウザで開くか、ローカルサーバーで配信してください。

```bash
cd games/third-person-boxer-3d
python3 -m http.server 8080
# http://localhost:8080 を開く(スマートフォンの縦画面を想定)
```

- **左スワイプ**: キャラクターが左へ素早く移動しながら、上半身を
  左へ大きく傾け、腰を落として膝を曲げ、パンチを紙一重で避けるような
  姿勢を取る。移動・姿勢とも一瞬で最大になったあと、起き上がり
  小法師のように素早くニュートラル姿勢へ戻る
- **右スワイプ**: 左スワイプと完全に左右反転した動作
- **左へ回避中に右スワイプ**(またはその逆): 新たに逆方向へ移動する
  のではなく、ニュートラル位置への復帰動作を通常より速くする

## 仕組みメモ

### カメラ

参照写真は「頭が地平線のすぐ下に来て、キャラクターが画面下半分を
大きく占める、やや見下ろし気味の三人称視点」という構図だったため、
`computeCameraPose()`で以下のパラメータを調整して再現している。

- 視野角(FOV) 42度
- カメラ高さ 1.85(キャラクターの頭の高さよりやや上)
- カメラ距離 3.0(キャラクターの背後、Z軸プラス方向)
- 注視点の高さ 1.5(カメラよりやや低い位置を見ることで、緩やかな
  見下ろし角度をつけている)

キャラクターは原点に立たせ、`player.rotation.y = Math.PI`で180度
回転させることで背中をカメラ側に向けている。

### 地面のグリッド

当初はCanvasで描いたグリッド柄のテクスチャをタイル状に繰り返し
貼る方式を試みたが、非常に大きな単一平面上ではタイルの境界線が
期待通りに繰り返し表示されず(High-DPIで確認するとタイル自体は
正しく生成されているにもかかわらず、通常解像度では極端に見えにくい
という問題があった)、代わりに実際の3Dライン形状である
`THREE.GridHelper`を単色の地面メッシュの上に重ねる方式に変更した。
こちらは常に確実に描画される。

### キャラクター

頭・首・胴体(カプセル)・腰・短パン(シリンダー)・脚(カプセル×2本
×2脚)・腕という構成。腕は「肩→肘→拳」の3点をワールド座標で指定し、
2点間を結ぶカプセルを生成する`segmentMesh()`ヘルパーで構築することで、
参照写真のような「肘が体側に張り出し、拳は胸の前(＝背面からは隠れる
側)に来るガードの構え」を再現している。

接地シャドウは、動的なシャドウマップではなく、放射状グラデーションを
描いたCanvasテクスチャを地面に薄く重ねる「フェイクシャドウ」方式に
している(参照写真の柔らかい影の見た目に近いため)。シャドウは
キャラクターの左右移動に追従する。

### 左右スワイプでの回避移動

Three.js非依存の純粋関数として実装しているため、Node上でロジックだけを
単体テストできる。

- `classifySwipe(dx, dy, dt)`: ポインターの移動量・時間から左右
  スワイプを判定する(縦方向の移動が大きすぎる、移動量が小さすぎる、
  時間がかかりすぎている場合はスワイプと見なさない)
- `onSwipe(state, direction, now, currentX)`: スワイプ方向を受けて
  次の状態を返す。現在と逆方向への「ディフェンス中」の逆スワイプが
  来た場合は、ニュートラルへの復帰(`return`)を通常より短い
  duration(`FAST_RETURN_MS`)で即座に開始する。それ以外は目的方向
  (`DODGE_X`)へ向かう`out`フェーズを(再)開始する
- `advanceDodge(state, now)`: `out`フェーズの時間が経過したら自動的に
  `return`フェーズへ、`return`フェーズの時間が経過したらニュートラルの
  空状態へ遷移させる
- `computeDodgeX(state, now)`: 経過時間をイーズアウト(`easeOutCubic`)
  で補間し、現在のX座標を返す

毎フレーム`advanceDodge`→`computeDodgeX`の結果を`player.position.x`
(および接地シャドウの位置)に反映しているだけで、パンチや被弾などの
判定は一切持たない。

### 回避姿勢(上半身の傾き・腰落とし・膝の曲げ)

`computeDodgeX(state, now)`をそのまま`DODGE_X`で割ることで、
X移動と完全に同期した「回避の進行度」(`computeDodgeProgress`、
-1=左いっぱい〜0=ニュートラル〜+1=右いっぱい)を求め、これ1つを
入力に`computeDodgePosture(progress)`が以下の姿勢パラメータを返す
(すべてThree.js非依存の純粋関数)。

- `leanZ`: 上半身を回避方向へ傾ける角度。符号は`progress`と同じ
  (左回避なら負)
- `leanX`: 上半身を前へかがめる角度(パンチを潜り抜けるような前傾。
  左右どちらの回避でも同じ量だけ前傾する)
- `crouchDrop`: 腰を落とす量(キャラクター全体のY座標を下げる)
- `hipBend` / `kneeBend`: 股関節を前へ曲げる角度と、膝でその逆方向に
  大きめに曲げ返す角度。単純に脚を前に振り出すのではなく、膝から
  下だけ後ろへ戻すことで「足を大きく踏み出しすぎない、その場で
  重心を落とす」しゃがみ姿勢に近づけている

これらはすべて`|progress|`(回避の深さ)に比例するため、回避の
移動距離が最大になる瞬間(`out`フェーズ終了時、開始から140ms)に
姿勢も最も深くなり、`return`フェーズで移動と姿勢が同時に
ニュートラルへ戻る。

反映先は以下の通り(既存のキャラクター構造を、回避時に回転させられる
よう腰の高さ(`upperBody`)・股関節(`hipPivot`)・膝(`kneePivot`)を
支点とするグループに再構成している)。

- `upperBody`(胴体・首・頭・腕をまとめたグループ、腰の高さを支点に
  配置): `rotation.z`に`leanZ`、`rotation.x`に`leanX`
- 左右の脚の`hipPivot`: `rotation.x`に`hipBend`(両脚とも同じ値、
  回避方向に関わらず対称に曲げる)
- 左右の脚の`kneePivot`: `rotation.x`に`kneeBend`
- `player.position.y`: `-crouchDrop`

キャラクターは背中をカメラに向けて180度回転しているため、
「回避方向と同じ符号で上半身を傾けると画面上でも同じ方向に見える」
という向きの整合性は、実際に頭部のワールド座標を測定して検証済み。

## テスト

Playwrightで以下を確認した。

- シーン・カメラ・地面・グリッド・キャラクターグループが正しく
  初期化されていること
- カメラがキャラクターの背後(Z>0)かつ頭上より高い位置(Y>1.5)に
  あること
- キャラクターグループが180度回転して背中をカメラに向けていること
- 空のグラデーションテクスチャとフォグが設定されていること
- 実際に描画されたcanvasのピクセルに十分な色のバリエーションがあり、
  単色の空白画面になっていないこと
- ウィンドウサイズ変更後にカメラのアスペクト比が追従すること
- `classifySwipe`が左右スワイプを正しく判定し、遅すぎる/縦方向すぎる/
  短すぎる入力を弾くこと
- 左スワイプで`out`フェーズが開始し、時間経過で自動的に`return`
  フェーズ、さらにニュートラルへと遷移すること
- 逆方向スワイプが`out`中・`return`中のどちらで来ても、通常より短い
  durationの`return`に切り替わること(特殊挙動)
- 同方向スワイプの再入力は`out`フェーズを再開始するだけであること
- 実際にタッチスワイプ操作を行い、キャラクターが左右へ移動した後
  ニュートラル位置(x=0)へ戻ることを画面上の値で確認
- `computeDodgePosture`がニュートラル(0)で全パラメータ0を返すこと
- 左右いっぱいの回避姿勢が、上半身の傾き以外(前傾・腰落とし・
  股関節/膝の曲げ)すべて左右対称な値になること(完全な左右反転)
- 回避の深さ(`|progress|`)が浅いほど姿勢パラメータの絶対値も
  小さくなること
- 膝が股関節と逆方向により大きく曲がる(その場でのしゃがみに
  近づける)こと
- `computeDodgeProgress`が`out`フェーズ終了時にちょうど-1/+1に
  達すること
- 実際にスワイプ後、数フレーム後の実シーンで、キャラクター全体が
  下がり(しゃがみ)、上半身が回避方向へ傾き(符号が正しいことを
  頭部のワールド座標で確認済み)、前傾し、両脚が対称に股関節から
  曲がっていること

いずれもコンソールエラーなし(favicon 404を除く)で成功している。
