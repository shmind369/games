# ドラッグ＆マグネット式カレンダーアプリ

「予定を入力するから、予定を配置するへ」という企画書をもとに作成した
プロトタイプです。一般的なカレンダーアプリのように日付・時刻を選択・
入力して予定を保存するのではなく、「予定カードをカレンダーの時間軸へ
ドラッグして置く」という操作だけで日時を決められるようにしています。

ゼルダの伝説『ティアーズ オブ ザ キングダム』のウルトラハンド・
スクラビルドのように、内部では日時を正確に管理しながら、ユーザーには
直感的なドラッグ操作だけを見せる、という操作思想を着想のヒントにして
います。

企画書の「5. 初期プロトタイプの目標」に挙げられた最小機能に絞って
実装しています。

- 予定カードの作成・表示
- ドラッグによる移動
- 時間軸へのマグネット吸着
- 配置した位置に応じた日時の設定
- ドラッグによる日時の再変更

通知機能・繰り返し予定は企画書の方針通り対象外です。

## 遊び方

`index.html` をブラウザで開くか、ローカルサーバーで配信してください。

```bash
cd games/drag-magnet-calendar
python3 -m http.server 8080
# http://localhost:8080 を開く(スマートフォンでの操作を想定)
```

- 上部の入力欄に予定の内容(「歯医者」「サランラップを買う」など)を
  入力し、「追加」ボタンまたはEnterキーで予定カードを作る。作った
  カードは日時が未定のまま、入力欄のすぐ下の**待機トレイ**(横スクロール
  できるカード置き場)に並ぶ
- 待機トレイのカードを指(またはマウス)でつかみ、下のカレンダーの
  時間軸へドラッグする。カレンダーの上に入ると、カードが最も近い
  **15分単位の時刻へ自動的に吸着(マグネット)**し、ドラッグ中もその
  時刻にスナップしたまま追従する。指を離すと、その時刻でその日の予定
  として配置される
- 配置済みのカードも同じようにドラッグでき、カレンダー内で上下に
  動かすと別の時刻へ再配置できる(日付は現在表示中の日のまま。日付を
  またぐ移動は今回のスコープ外)
- 配置済みのカードを**画面の上の方(待機トレイの高さ)まで持ち上げる**と、
  「ここまで持ち上げると未配置に戻ります」という表示が出る。そのまま
  指を離すと、その予定は未配置(待機トレイ)へ戻る
- カレンダーが24時間ぶんあり画面に収まらない場合、ドラッグ中に画面の
  上端・下端付近まで指を持っていくと自動的にスクロールする
- 各カードの右上の「×」ボタンでその予定を削除できる
- 「‹」「›」で前日・翌日へ、「今日」ボタンで今日に戻る(いずれも
  ドラッグではなくボタン操作。日付をまたいだドラッグでの移動は今後の
  検討事項のため、今回は未対応)
- 入力した予定・配置した日時はブラウザの`localStorage`に自動保存され、
  再読み込みしても消えない

## 仕組みメモ

### データモデル

1つの予定は、Three.js等の描画ライブラリに依存しない単純なJavaScript
オブジェクトとして持っている。

```js
{ id, text, date, startMinutes, durationMinutes }
```

`date`(`"YYYY-MM-DD"`)と`startMinutes`(0時からの分数)がどちらも
`null`の間は「未配置」として扱われ、待機トレイに表示される。両方に
値が入ると「配置済み」としてカレンダーの該当する日・時刻に表示される。
所要時間(`durationMinutes`)は企画書で「今後の検討事項」とされている
「予定の所要時間の設定方法」にあたるため、今回は固定値(60分)のみで
変更する手段を設けていない。

### 1日ビューを採用した理由

企画書では「カレンダーの時間軸」という表現にとどまり、週表示・月表示
までは指定されていない。一方で「④マグネット機能」「⑤配置後の変更」は
コア機能として明記されている一方、「日付をまたぐ移動への対応」は
「6. 今後の検討事項」に明示的に挙げられている。この2つを素直に
両立させる構成として、**カレンダー側は常に1日ぶんの時間軸だけを表示し、
日付の切り替えは(ドラッグではなく)前日/翌日/今日ボタンで行う**という
設計にした。これにより、

- カレンダー内でのドラッグは常に「同じ日の中で時刻だけを変える」操作に
  自然と限定され、複数日を横断する複雑な当たり判定やスクロール制御を
  今回は実装せずに済む(日付をまたぐドラッグ移動への対応は、将来
  複数日ぶんのカラムを並べるレイアウトに拡張する際の課題として
  README「今後について」にそのまま引き継いでいる)
- 「操作感を検証する」という初期プロトタイプの目的に対して、週表示の
  ヘッダー・横スクロールなどの付随的なUIを作り込まずに、ドラッグ&
  マグネットそのものの感触に実装の手数を集中できる

### マグネット(吸着)の実装

ドラッグ中、指(ポインタ)がカレンダーの当日カラムの上にあるかどうかを
`calendarScroll`要素(スクロールしても矩形自体は動かない、見えている
ビューポート)の`getBoundingClientRect()`で判定する。カラムの上に
いる間は、ポインタのY座標を分単位の時刻に変換し、`SNAP_MINUTES`
(15分)単位の最も近い値に丸めて、**カード自身(ドラッグ中はフロート
表示のゴースト)をその時刻の位置へアニメーションさせながら吸着させる**
(CSSの`transition`で短く・バネ気味に動かすことで、Ultrahand/
スクラビルドのような「吸い付く」感触を狙っている)。カラムの外(待機
トレイに指を戻したときなど)ではスナップせず、指の位置にそのまま
追従する。

吸着先の時刻を求める座標計算では、スクロールされる中身の要素
(`dayColumnWrap`、24時間ぶんの高さを持つ)の`getBoundingClientRect()`
をそのまま使っている。この値は常にスクロール後の実際の画面上の位置を
返すため、スクロール量(`scrollTop`)を別途足し引きする必要はない
(実装中、一度`scrollTop`を二重に加算してしまい、スクロールした状態で
ドラッグすると吸着先の時刻がずれるという不具合を作り込んでしまったが、
テストで検出して修正した)。

### ドラッグ中はフロート表示のゴーストに差し替える

待機トレイのカードは横スクロールするフレックスボックスの通常の
レイアウトの中にあり、配置済みのカードはカレンダーの当日カラム内に
絶対位置指定されている。この2つの異なる配置方式をまたいでドラッグ
操作を統一的に扱うため、ドラッグ確定(`DRAG_THRESHOLD_PX`=6px以上の
移動)と同時に元のカード要素を透明にし、代わりに`position: fixed`の
ゴースト要素(`#ghost`)を指に追従させる。指を離した時点で初めて、
実際のデータ(`date`/`startMinutes`)を確定し、元の要素を適切な
コンテナ(待機トレイ/当日カラム)に再配置する。

### 未配置へ戻す(上に持ち上げて離す)

配置済みのカードをドラッグして、カレンダーの外(かつ画面上部
`clientY < 90`)まで持ち上げると、「ここまで持ち上げると未配置に
戻ります」という帯状のヒントを表示する。この状態で指を離すと、
`date`/`startMinutes`を両方`null`に戻し、待機トレイへ戻す。待機
トレイへの新規追加(入力して「追加」する)と、配置済みカードを
未配置に戻す操作が、どちらも同じ「`date`が`null`かどうか」という
1つの状態だけで表現されるため、特別な分岐をほとんど増やさずに実装
できている。

### ポインタイベントでのドラッグ(マウス・タッチ両対応)

このリポジトリの他の2Dプロトタイプ(`card-canvas`等)と同じく、HTML5の
ネイティブDrag and Drop APIではなく、`pointerdown`/`pointermove`/
`pointerup`による自前のドラッグ実装にしている(タッチデバイスでの
挙動が安定しているため)。`touch-action: none`をドラッグ対象のカードに、
`touch-action: pan-y`をカレンダーのスクロール領域に、`touch-action:
pan-x`を待機トレイにそれぞれ指定し、ブラウザ標準のスクロール・
ズームジェスチャーとドラッグ操作が競合しないようにしている。

`setPointerCapture`は一部のブラウザ・疑似的なポインタイベントでは
失敗することがあるため、`try/catch`で囲み、失敗してもドラッグ自体は
継続できるようにしている(失敗時はポインタキャプチャなしで通常の
バブリングに頼る形になるが、実機のタッチ/マウス操作では通常成功する)。

### カレンダーの端までドラッグすると自動スクロール

24時間ぶんの時間軸は画面に収まりきらないため、ドラッグ中にポインタが
カレンダー表示領域の上端・下端から`EDGE_AUTOSCROLL_PX`(36px)以内に
入ると、`requestAnimationFrame`で`calendarScroll`を一定速度
スクロールし続ける。範囲外に出る、またはドラッグが終わるとスクロールは
止まる。

### 「現在時刻」ライン

表示中の日付が今日の場合だけ、現在時刻の位置に赤い横線を表示する
(`setInterval`で30秒ごとに再計算)。カレンダーが「今どの時間帯を
見ているか」を把握しやすくするための、企画書の要件には直接ないが
小さな補助表示。

### 永続化

`localStorage`に`schedules`配列をそのまま`JSON.stringify`して保存する
簡易な方式にしている(このプロトタイプの規模では十分)。ページを
開くたびに読み込み、変更のたびに保存するだけで、サーバーサイドの
実装は持たない。

## テスト

Playwrightで以下を確認した。

- 入力欄に予定名を入れて「追加」(またはEnterキー)を押すと、`date`/
  `startMinutes`が`null`の「未配置」の予定が作成され、待機トレイに
  表示されること。入力が空/空白のみの間は追加ボタンが無効化される
  (CSSの`disabled`状態込み)こと
- 待機トレイのカードをマウス操作でドラッグし、カレンダーの9:33付近へ
  ドロップすると、`SNAP_MINUTES`(15分)単位で最も近い9:30に
  スナップされ、`date`に表示中の日付が、`startMinutes`に570
  (9:30)が設定されること。ドラッグ中、しきい値(6px)を超えた時点で
  フロート表示のゴーストが現れること
- 配置済みのカードを再度ドラッグして別の時刻(14:15)へ移動すると、
  `startMinutes`だけが更新され、`date`は`null`に戻らない(=未配置に
  なってしまわない)こと。この際、目的の時刻が初期スクロール位置では
  画面外にある状態から、カレンダー下端付近まで指を持っていくと実際に
  自動スクロールが働き、スクロール後の位置で正しい時刻にスナップ
  できること
- 配置済みのカードを画面上部(待機トレイの高さ)までドラッグして
  持ち上げると「ここまで持ち上げると未配置に戻ります」のヒントが
  表示され、そのまま離すと`date`/`startMinutes`が両方`null`に戻り
  待機トレイへ戻ること
- しきい値未満の移動(実質的なタップ)では何も変化しないこと(誤操作で
  意図せず配置されないことの確認)
- カードの「×」ボタンでその予定が削除されること
- 「›」(翌日)ボタンで表示中の日付が変わり、「今日」ボタンで元の
  日付に戻ること
- 待機トレイのカードを、カレンダーの外(日付ナビゲーションの帯の上)に
  ドロップすると、未配置のままで例外も発生しないこと
- 当日の23:50付近へドロップすると、1日の終わり(24:00)を超えないよう
  23:00(1440分-60分)にクランプされること
- 実際のタッチジェスチャー(Chrome DevTools Protocolの
  `Input.dispatchTouchEvent`で`touchStart`/`touchMove`/`touchEnd`を
  発行)でも、マウスでのドラッグと同じ結果(9:00へスナップして配置)に
  なること。素朴に`new PointerEvent(...)`を手動で`dispatchEvent`する
  方法では、ブラウザの実際の入力パイプラインを経由しないため
  `setPointerCapture`が正しく機能せずドラッグが成立しないことが
  分かり、CDPの`Input.dispatchTouchEvent`を使う方式に切り替えて
  確認した
- 各要素の`touch-action`計算値が意図通り(カード: `none`、カレンダー:
  `pan-y`、待機トレイ: `pan-x`)であること
- ページを再読み込みしても、`localStorage`経由で予定(配置済みの日時
  込み)がそのまま復元されること

いずれもコンソールエラーなし(favicon 404を除く)で成功している。

## 今後について

企画書「6. 今後の検討事項」に挙げられた項目のうち、今回のプロトタイプ
では以下は意図的に対象外にしている。

- **マグネットの吸着間隔と吸着範囲**: 現状は15分固定(`SNAP_MINUTES`
  定数)。吸着が効き始める距離による制限もなく、カレンダー上であれば
  常に最寄りの15分に吸着する。間隔の変更UIや、吸着しない「自由配置
  ゾーン」などは未実装
- **スマートフォンでの操作性**: タッチイベント・`touch-action`の
  設定・自動スクロールなど基本的な配慮はしているが、実機での最終的な
  チューニング(ゴーストの大きさ、吸着のアニメーション速度など)は
  今後の検証次第で調整が必要になる可能性がある
- **予定の所要時間の設定方法**: 現状60分固定。将来的には、配置済み
  カードの下端をドラッグして伸縮させる、といった操作が候補になる
- **日付をまたぐ移動への対応**: 今回は1日ビュー+前日/翌日ボタンという
  構成のため、ドラッグでの日付変更自体が発生しない設計にしている。
  複数日(週表示など)を並べて、日をまたぐドラッグに対応するのは
  今後の拡張
- **日時未設定の予定の管理方法**: 待機トレイへの表示、配置済みカードを
  持ち上げて未配置へ戻す操作までは実装したが、未配置の予定が大量に
  増えた場合の整理(並び替え・検索・古い未配置予定の扱いなど)は
  今回のスコープ外

その他、プロトタイプとして意図的に実装していない範囲。

- 予定の文言編集(削除して作り直す運用。テキスト入力欄からの再編集UIは
  未実装)
- 通知機能・繰り返し予定(企画書で明示的に対象外とされている)
- 複数の予定が同じ時間帯に重なった場合の見た目の調整(現状は単純に
  重なって表示される)
