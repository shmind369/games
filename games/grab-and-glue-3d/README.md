# 一人称視点3D建築システム(Grab & Glue 3D)

開発指示書(v0.1)「一人称視点3D建築システム」をもとに作成したプロトタイプです。

『ゼルダの伝説 ティアーズ オブ ザ キングダム』の「ウルトラハンド」に
着想を得た、一人称視点で物体をつかみ・動かし・接着して構造物を組み立てる
操作感のプロトタイプです。指示書の方針通り、特定のゲームの素材・UIを
複製するのではなく、「物体を自由に動かし、組み合わせて構造物を作る」と
いう基本的な遊びだけを独自に実装しています。

指示書「8. 開発優先順位」に挙げられた順番(一人称視点と移動→照準による
選択→つかむ→移動・回転・手放す→接着・解除→一体操作→スマートフォン向け
UI調整→実機確認相当のテスト)で実装しました。

## 遊び方

`index.html` をブラウザで開くか、ローカルサーバーで配信してください。

```bash
cd games/grab-and-glue-3d
python3 -m http.server 8080
# http://localhost:8080 を開く(スマートフォンでの操作を想定)
```

- 画面左下の仮想スティックで前後左右に移動する
- 画面右側をドラッグすると視点(カメラの向き)が変わる
- 画面中央の照準(レティクル)が木材(板・丸太)に重なると、照準が黄色く
  光り、対象が黄色くハイライトされる。この状態で「つかむ」ボタンを押すと
  持ち上げる
- つかんでいる間、物体は視点から一定距離・一定の高さを保ってカメラの前に
  浮遊し、視点を動かすとついてくる(直感操作)。画面右側の補助ボタンで
  上下移動・前後移動(近づける/遠ざける)・回転(15度刻み、長押しで連続)の
  微調整ができる(精密操作)。この2つは同時に併用できる
- つかんだ物体を別の木材に近づけると、近づいた相手が緑色に光り「接着」
  ボタンが有効になる。押すと、その時点の相対的な位置・角度を保ったまま
  2つの物体が接続され、手が離れる(自動的に手放される)。続けて別の木材を
  つかんで、できた構造物へさらに接着していくことで、複数の物体を連続して
  つなげられる
- 接着済みの構造物は、そのうちどの1つをつかんでも、つながった全体が
  一体として持ち上がる
- 何もつかんでいない状態で、接着済みの木材に照準を合わせると「解除」
  ボタンが有効になる。押すと、その木材だけが構造物から切り離され、残りの
  部分は(切り離した結果でさらに分かれる場合も含めて)引き続き正しくまとまる
- つかんでいる間に「解除」を押すと、接着せずにその場で手放せる(「つかむ・
  接着・解除」の3ボタンのうち、解除ボタンは状況に応じて「手放す」と
  「接着解除」の両方を兼ねる。詳細は後述「仕組みメモ」を参照)

## 仕組みメモ

### 「解除」ボタンの二重の役割

指示書の画面構成では、下部のボタンは「つかむ・接着・解除」の3つだけが
明記されている(5.「手放す」機能と、6.「接着済みの接続を選択し解除する」
機能は、ボタンの数としては別々に説明されているが、画面構成ではこの3つに
まとめられている)。これを素直に実装するため、「解除」ボタン1つに
文脈に応じた2つの意味を持たせた。

- 何かをつかんでいる間に押す → つかんでいる物体をその場に手放す
  (指示書5.「手放す」に対応)
- 何もつかんでおらず、接着済みの木材に照準を合わせている間に押す →
  その木材を構造物から切り離す(指示書6.「接着済みの接続を選択し
  『解除』ボタンで分離」に対応)

ボタンの有効/無効は毎フレーム状態に応じて切り替わり(指示書9.「操作状態に
応じて使用可能なボタンを切り替える」)、上部のステータス表示にも
「照準の木材: つかむ、または解除で分離」のようにその時点でどちらの
意味になるかのヒントを出している。

### データモデル: パーツ・構造物グループ・接続の3層構造

- **パーツ(piece)**: `{ id, kind, mesh, groupId }`。板・丸太それぞれの
  実体。見た目(ジオメトリ・マテリアル)が違うだけで、つかむ・接着の
  ロジックからは区別しない
- **構造物グループ(group)**: `{ id, root: THREE.Group, memberIds }`。
  「一緒に動くパーツの集まり」の入れ物。未接着のパーツは「自分1つだけの
  グループ」に属している。グループの`root`を動かせば、所属する全パーツが
  一緒に動く(指示書6.「接着した物体群は一つの構造物として操作できる」に
  対応)
- **接続(connection)**: `{ id, a: pieceId, b: pieceId }`。どのパーツと
  どのパーツが接着されているかの記録。グループの統合・分離とは独立して
  保持しておくことで、「解除」時にどのパーツ同士がまだ繋がっているかを
  グラフとして正しく再計算できるようにしている

この3層に分けたことで、「2つのグループを1つに統合する(接着)」
「1つのグループから特定のパーツを取り除き、残りを連結成分ごとに
作り直す(解除)」という2つの操作を、それぞれ独立した関数
(`glueGroups`/`detachPiece`)としてシンプルに実装できた。

### 接着: ワールド変形を保ったままの付け替え

接着は、Three.jsの親子関係(`parent.add(child)`)でパーツを一方の
グループの`root`の子にするだけで実現している。ただし単純に`add()`する
だけでは、親から見た相対位置(ローカルTransform)が変わらないまま新しい
親の座標系で解釈されてしまい、見た目の位置がズレてしまう。これを防ぐため
`reparentPreservingWorldTransform`という、付け替え前後でワールド変形
(位置・回転・拡大率)が変わらないようローカルTransformを逆算するヘルパーを
用意している(`humanoid-gltf-exporter`のGLBインポート機能で使った手法と
同じ考え方を、このプロジェクト用に独立して実装したもの)。

### 解除: 接続グラフの連結成分としての再計算

1つのパーツを構造物から切り離す際、そのパーツが関わる接続(`connection`)を
すべて削除したうえで、残ったパーツ同士が接続エッジを通じてまだ繋がって
いるかどうかを幅優先探索(BFS)で連結成分ごとに求め直し、成分ごとに
新しいグループへ作り直している(`mesh-modeling-studio`のスキニング用
連結成分検出と同じUnion-Find的な考え方)。

これにより、例えば板A-B-Cが「A⇄B」「B⇄C」の2本の接続で一列に繋がって
いる状態で、橋渡し役のBを解除すると、A・B・Cの3つがそれぞれ独立した
構造物に分かれる(AとCの間には元々直接の接続が無いため)、という
グラフ理論的に正しい挙動になる。実際にPlaywrightで3つのパーツを
鎖状に接着し、中間のパーツを解除して3つに分かれることを確認している。

### つかんで運ぶ: 直感操作(追従)と精密操作(手動オフセット)の合成

つかんでいる間、毎フレーム「カメラの位置から前方`holdDistance`だけ
進んだ点」を基準位置として求め、そこへ`held.holdHeight`(補助ボタンで
調整する上下オフセット)を加えた点を目標位置とする。構造物グループの
`root.position`をこの目標位置へ`lerp`(線形補間)で少しずつ近づけることで、
視点を動かすと物体もついてくる「直感操作」と、滑らかに追従する(指示書9.
「操作中の物体が突然飛んだり、意図しない方向に移動したりしないように」)
挙動の両方を実現している。

補助ボタンによる「精密操作」(上下移動・前後移動・回転)は、この
`holdHeight`/`holdDistance`、またはグループの`root.rotation.y`を直接
書き換えるだけで、直感操作(毎フレームの追従計算)とは別の値として
保持している。そのため2つの操作方式は干渉せず、同時に併用できる
(指示書5.「直感操作と精密操作を併用できるハイブリッド方式」)。

精密操作ボタンはタップで1段階(上下18cm相当・前後28cm相当・回転15度)
動き、350ms以上押し続けると90ms間隔で繰り返し段階が進む(長押しで
連続微調整できるようにするため)。

### 接着可能な状態の検出とハイライト

つかんでいる間、保持中の構造物に属する各パーツの中心から、それ以外の
すべてのパーツの中心までの距離を毎フレーム調べ、最も近いものが
`GLUE_RANGE`(0.85)以内であれば、そのパーツを「接着対象」として緑色に
ハイライトし、「接着」ボタンを有効にする(指示書6.「物体をつかんで別の
物体に近づけると、接着可能な状態を視覚的に表示する」)。対象が照準による
選択(黄色、つかむ前)と同じ`setPieceHighlight`の仕組みを色違いで
共有しているため、新しいハイライトの仕組みを別途作らずに済んでいる。

### 照準(レイキャスト)による選択

画面中央のNDC座標`(0, 0)`から`THREE.Raycaster`でレイを飛ばし、全パーツの
メッシュと交差判定して最も近いものを「照準中」として扱う(指示書4.
「画面中央の照準からRaycasterを使用してレイを飛ばし、対象となる物体を
判定する」)。判定距離は`GRAB_REACH`(7.5)に制限しており、遠くの物体を
誤って掴めないようにしている。つかんでいる間はこの照準判定を行わず
(掴んだまま別の物体を選択できてしまうと混乱するため)、代わりに
接着対象の近接判定だけを行う。

### 移動・視点操作・UIレイヤーの構成(スマートフォン向け)

`weight-of-keys-3d`等このリポジトリの他の一人称視点3Dプロトタイプと
同じ構成を踏襲している。

- 移動は左下の仮想スティック(`pointerdown`/`pointermove`/`pointerup`の
  自前実装、HTML5 Drag and Drop APIは不使用)
- 視点操作は全画面を覆う透明レイヤー(`#lookLayer`)へのドラッグだが、
  指示書の「画面右側:視点操作用のタッチ領域」に合わせて、**ドラッグを
  開始した時点のタッチ位置が画面幅の42%より右**にある場合だけ視点操作を
  開始するようにしている(開始後はそのまま画面のどこまでdrag しても
  追従する)。画面左側(仮想スティック寄り)から始めた指の動きが、
  誤って視点を動かしてしまわないようにするための制限
- ボタン類(仮想スティック・メイン3ボタン・補助ボタン)は`z-index`を
  視点操作レイヤーより高くし、それぞれのタップがレイヤーに吸われずに
  ボタン自身で受け取られるようにしている

**実装中に見つけて修正した不具合**: 当初、下部中央に配置していた
「つかむ・接着・解除」の3ボタンが、横幅の狭い画面(390px前後の
スマートフォン相当)では左下の仮想スティックと重なってしまい、
スティックをタップしたつもりが実際には裏に隠れた「つかむ」ボタンへ
タップが吸われてしまう不具合があった(Playwrightで`elementFromPoint`を
使い、意図した要素が実際にタップを受け取れているかを検証して発見)。
ボタン列の左端を仮想スティックの右端より内側に入らないよう
`clamp(126px, 30vw, 150px)`で確保し、ボタン自体の最小幅も詰めることで
解決した。

### 地面突き抜け・物体のめり込み対策(簡易版)

指示書9.の「カメラが地面を突き抜けたり、物体が視界にめり込んだりしない
ようにする」に対して、今回は本格的な衝突判定ではなく以下の簡易対策のみ
行っている(指示書9.「初期段階では本格的な物理演算エンジンの導入を
必須としない」「接着と物理演算は別々に設計し、段階的に実装する」との
方針に沿ったもの)。

- プレイヤーの足元の高さは常に`EYE_HEIGHT`に固定し、地面(平面)より
  下がらないようにしている(今回のフィールドは平坦な地面のみのため
  これで十分)
- つかんでいる物体の高さは、精密操作でどれだけ下げても一定値
  (0.22)より下がらないようクランプしている
- つかんでいる物体とカメラの距離は`HOLD_DISTANCE_MIN`(1.1)未満に
  ならないようクランプしており、カメラのニアクリップ面(0.05)へ
  めり込むことはない

いずれもパーツの正確なバウンディングボックスを考慮した厳密な判定では
ない簡易的なものだが、指示書が想定する範囲(板・丸太程度のサイズの
物体、平坦な地面)では実用上問題にならないことをテストで確認している。

## テスト

Playwrightで以下を確認した。

- 起動直後は開始画面が表示され、「はじめる」を押すとフィールドに入ること
- プレイヤーが照準で木材を正しく捉えられること(照準の黄色ハイライト・
  「つかむ」ボタンの有効化)
- 「つかむ」で対象を持ち上げられること、つかんだ物体が元の位置から
  視点方向へ実際に移動すること
- 補助ボタン(上/下/前/後/回転)のタップで、つかんでいる物体の高さ・
  距離・向きがそれぞれ1段階ずつ変化すること。ボタンを押し続けると
  連続して変化すること(長押しリピート)
- つかんだ物体を別の木材に近づけると、相手が緑色にハイライトされ
  「接着」ボタンが有効になること。押すと2つの物体が1つの構造物
  グループへ統合され、保持状態は自動的に解除されること
- 接着済みの構造物をどちらのパーツからつかんでも、構造物全体が1つの
  剛体として一緒に移動すること(構成パーツ間の相対距離が移動前後で
  変化しないことを数値で確認)
- 3つの木材を鎖状(A⇄B⇄C)に連続して接着できること。橋渡し役(B)を
  「解除」すると、A・B・Cの3つがそれぞれ独立した構造物に正しく
  分かれること(連結成分の再計算が正しく機能していることの確認)
- 何もつかんでいない状態で接着済みの木材に照準を合わせると「解除」
  ボタンが有効になり、押すとその木材だけが構造物から切り離されること
- つかんでいる間に「解除」を押すと、接着先が近くになくてもその場で
  手放せること(接続は作られないこと)
- 実際のタッチジェスチャー(Chrome DevTools Protocolの
  `Input.dispatchTouchEvent`)で、仮想スティックのドラッグが実際に
  プレイヤーを移動させること、画面左側から始めたドラッグは視点を
  回転させず、画面右側から始めたドラッグは視点を回転させること
  (「画面右側:視点操作用のタッチ領域」の確認)
- 各要素の`touch-action`計算値が意図通り(キャンバス・スティック:
  `none`、メインボタン: `manipulation`)であること
- 横画面(ランドスケープ)にすると、縦画面を促すオーバーレイが表示
  されること
- `node --check main.js`でシンタックスエラーがないことを確認

いずれもコンソールエラーなし(favicon 404を除く)で成功している。

## 今後について

指示書「10. 完成条件」の8項目はすべて満たしている。一方、指示書で
明示的に簡易実装とされている範囲、および今回のテストを通じて
今後の課題として見えてきた点は以下の通り。

- **本格的な衝突・物理判定**: 指示書9.の方針通り、今回は物体同士の
  めり込み防止やパーツごとの正確な接地判定までは実装していない
  (簡易なクランプのみ)。段階的に、パーツのバウンディングボックスを
  考慮した接地・衝突判定を追加する余地がある
- **接着位置の自動整列(スナップ)**: 現状の接着は「つかんだ時点の
  位置・角度をそのまま固定する」方式で、面同士を自動的に平行・隣接
  させるような吸着(スナップ)は行っていない。指示書も「初期実装では
  接着対象同士の相対的な位置と角度を維持する方式でよい」としており、
  今回はその最小実装にとどめている
  。将来的には、パーツの面や端点同士を検出して自動整列させる拡張が
  考えられる
- **フィールドの拡張**: 指示書7.の最小構成(地面・木の板3枚・丸太2本)
  のみを実装している。パーツの種類・数を増やす場合も、`createPiece`
  関数にジオメトリ・マテリアルを渡すだけで対応できる設計にしてある
- **複数の接着ペアの同時解除**: 「解除」は常に照準中の1パーツが関わる
  接続をすべて切り離す(≒そのパーツを孤立させる)仕様にしている。
  「特定の1本の接続だけを選んで切る」というより細かい単位の解除
  (例えばA-B-Cのうち、A-B間の接続だけを切ってB-Cは残す)は、指示書の
  「接着済みの接続を選択し」という表現により忠実に対応しようとすると
  別途「接続そのものを3D空間上で選択する」UIが必要になるため、今回は
  見送った
- **精密操作の軸追加**: 指示書5.に挙げられた上下・前後・回転(Y軸)の
  3種類のみ対応している。X/Z軸の回転など、より自由な角度調整は
  今回のスコープ外
