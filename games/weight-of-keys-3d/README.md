# WEIGHT OF KEYS

「鍵を集めるほど脱出に近づくが、重くなって追跡者から逃げにくくなる」という
リスク・リターンを中心に据えた、一人称視点の迷宮脱出ゲームです。Three.js製。

迷宮内に散らばる鍵を集めて出口の扉を開け、脱出するのが目的です。ただし
鍵は重く、持てば持つほど移動速度が落ちます。あなたより足の遅い追跡者も、
荷物が増えたあなたにはやがて追いつけるようになる――だからこそ、
「持っていくか、ここに置いていくか」の判断が常に問われます。

## 遊び方

`index.html` をブラウザで開くか、ローカルサーバーで配信してください。

```bash
cd games/weight-of-keys-3d
python3 -m http.server 8080
# http://localhost:8080 を開く
```

- 画面左下の**バーチャルスティック**で移動、**それ以外の画面をドラッグ**で
  視点を回転(タッチ・マウス両対応)
- 鍵に近づくと画面右下に「拾う」ボタンが出現、タップで拾得
- 「置く」ボタンで所持中の鍵一覧が開き、タップした鍵をその場に置ける
  (身軽になって移動速度が回復する。置いた鍵はあとで拾い直せる)
- 出口の扉は必要数の鍵を持っていないと赤く光ったまま開かない。必要数
  持って扉に近づけば脱出成功(緑色に変わる)
- 迷宮内には**追跡者**が徘徊している。プレイヤーは何も持っていなければ
  追跡者より速いが、鍵を持つほど重くなり、やがて追いつかれる
- 追跡者の位置は常に画面に表示されない。**足音**(左右のパンと音量で
  距離・方向を表現)を頼りに、どれだけ近いかを判断する
- 追跡者に追いつかれる、もしくは所持数が足りないまま出口には入れない
  ――捕まったらゲームオーバー、最初からやり直し

## 実装メモ

判定ロジックは`maze.js`にDOM/Three.js非依存の純粋関数としてまとめている
(Node上で直接動作確認できる)。

- `generateMaze` — 再帰的バックトラッカー法による奇数辺グリッド迷路生成
- `bfsDistances` / `bfsNextStep` — グリッド上のBFS最短経路。追跡者の
  追跡行動と、鍵・出口・追跡者初期位置のバランス配置(スタートから
  一定歩数以上離れた場所を選ぶ)の両方に使う
- `pickWanderStep` — 追跡者の徘徊(直前に来た方向へは戻りにくい)
- `speedFactorForWeight` / `playerSpeedForWeight` — 所持重量から速度
  倍率を導出する式。一定の重さを超えると、追跡者の速度を下回る
- `decidePursuerState` — 追跡者の索敵状態機械。視界(レイキャストで
  壁を貫通しないか判定)に加え、至近距離なら視界がなくても「聞こえて」
  追跡に切り替わる。見失っても数ティックは追跡を続ける「猶予」がある
- `chooseSpreadCells` — 鍵をスタートから一定距離以上、かつ互いに
  離れた位置へ広く配置する

`main.js`側では、追跡者の足音を`AudioContext`でその場合成し(低音の
「ドスッ」+ノイズの足音テクスチャ)、プレイヤーとの距離で音量、
戦闘状態(追跡中かどうか)でピッチをわずかに変化させ、方向は
`StereoPannerNode`で左右に振っている。
