# PHOTO SPIN 3D

1枚の写真を読み込むと、画像から被写体の奥行きをヒューリスティックに推測し、
指でドラッグして360度グルグル回して見られる疑似3Dビューアです。
Three.js製、深度マップによるメッシュ変形+テクスチャマッピングで実現しています。

## 遊び方(使い方)

`index.html` をブラウザで開くか、ローカルサーバーで配信してください。

```bash
cd games/photo-spin-3d
python3 -m http.server 8080
# http://localhost:8080 を開く
```

- 「画像を選ぶ」で好きな写真を読み込む
- **左右ドラッグ**で被写体を左右に回転、**上下ドラッグ**で上下に視点変更
- **ピンチ操作**で拡大・縮小
- 「リセット」で回転・ズームを初期状態に戻す

## 重要: このプロトタイプの深度推定はAIモデルではなくヒューリスティックです

当初のご指示は「AIによる深度推定」でしたが、実装時点でこのセッションの
ネットワークアクセスがnpm/PyPI等のパッケージレジストリのみに制限されており、
実際の深度推定モデルの重みファイルを配布している`tfhub.dev`・`huggingface.co`
等のホストへアクセスできないという環境上の制約がありました
(実際に`@tensorflow-models/depth-estimation`を取得して確認したところ、
npmパッケージ自体はJSコードのみで、モデル本体は実行時に`tfhub.dev`から
取得する仕組みでした)。

このため、**今回はAIモデルの代わりに、画像処理ヒューリスティックで
「深度マップ」を生成しています**(`main.js`の`computeDepthMap`)。
以下3つの古典的な単眼深度推定の手がかりを重み付け合成しています。

- **エッジ密度**(Sobelフィルタ): ピントが合っている(=輪郭がはっきりしている)
  領域ほど手前にある可能性が高い
- **画面中心からの距離**: 被写体は画面中央付近に配置されやすい
- **画面内の縦位置**: 画面下方にあるものほど手前(地面に接している)と仮定

生成した深度マップを実際にThree.jsのメッシュ頂点のZ座標に反映させて立体形状を
作り、元画像をテクスチャとして貼り付けています。「画像を単純に2D変形して
回しているように見せかける」のではなく、実際に**深度マップ→3Dメッシュ生成→
テクスチャマッピング→Three.js/WebGLで回転**という指示されたパイプライン構造
そのものは踏襲した上で、深度推定の中身だけがAIモデルからヒューリスティックに
置き換わっている状態です。将来的にモデル重みファイルを(別途アップロード等で)
入手できれば、`computeDepthMap`をONNX/TensorFlow.js推論に差し替えるだけで
本来の「AI深度推定」に切り替えられるよう、深度マップの生成部分と
メッシュ構築・描画部分を明確に分離した設計にしています。

## 仕組みメモ

- 判定・生成ロジックはThree.js描画から独立した純粋関数にしている
  - `computeDepthMap` — 上記のヒューリスティック深度マップ生成
  - `makeDepthSampler` — 低解像度の深度マップをバイリニア補間で
    メッシュの任意UV座標にサンプリングする関数
  - `computeDragRotation` / `computeCameraDistance` — ドラッグ回転・
    ピンチズームの純粋な数式部分
- 被写体は「前面(実写真テクスチャ、奥行きに応じて手前に隆起)」
  「背面(元画像を左右反転+ぼかし+暗めにしたテクスチャ、奥へわずかに隆起)」
  「側面リム(画像の縁の平均色で塞ぐ)」の3パーツで構成し、閉じた立体として
  360度どの角度から見ても破綻しないようにしている
  - 背面メッシュはY軸180度回転して配置しているため、前面と側面リムを
    正しく繋ぐには、背面側は**左右反転したグリッド座標**をサンプリングする
    必要がある(そのまま同じ座標で繋ぐとリムがねじれる)。この対応関係は
    `buildRimGeometry`のコメントで詳しく説明している
- 深度解析は画像を96×96に縮小した上で行い(計算コストを抑えつつ、
  滑らかな形状を得るため)、実際のテクスチャは長辺1024pxを上限に
  縮小してGPUテクスチャサイズを抑えている

## スコープ外(意図的に未実装。今後の改善予定)

  入手経路が確保できた場合に差し替え予定)
- 複数の被写体を個別に認識・分離する処理(現状は画像全体から単一の
  深度マップを推定するのみ)
- 背面・側面のより高精度な補完(現状は反転+ぼかしによる簡易的な補完)
