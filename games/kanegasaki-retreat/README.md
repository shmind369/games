# 金ヶ崎退き口

戦国時代・元亀元年(1570年)の「金ヶ崎の戦い」を題材にした、マス目移動・ターン制の
戦術シミュレーションRPGです。「織田信長の戦国史 × ファイアーエムブレム系のSRPG」
というコンセプトのもと、キャラクター・画像・音楽・UI・マップは既存作品をコピーせず、
実在の武将名と史実の枠組みだけを借りたオリジナル作品として制作しています。
素の2D Canvasで実装しています(Three.js等は未使用)。

このリポジトリの他のゲームと同様、いきなり大規模な内容を作るのではなく、
「金ヶ崎の戦い」1ステージだけを完成度高く仕上げることを優先しています。

## 遊び方

`index.html` をブラウザで開くか、ローカルサーバーで配信してください。

```bash
cd games/kanegasaki-retreat
python3 -m http.server 8080
# http://localhost:8080 を開く
```

- 自軍ユニットをタップして選択 → 移動可能範囲(青)がハイライトされる
- ハイライトされたマスをタップして移動 → 攻撃可能な敵がいれば赤くハイライトされ、
  行動メニュー(攻撃/特殊技/待機/やり直す)が表示される
- 「攻撃」で対象の敵をタップ(候補が1体のみなら自動選択)すると、攻撃力・命中率・
  予想ダメージ・撃破確率(反撃分も含む)を表示する戦闘予測画面が出る。「攻撃する」で
  戦闘実行
- 「出陣」を押すと、ファイアーエムブレム系SRPGの章冒頭のような会話デモが挟まる。
  タップで1行ずつ進む。右上の「スキップ」でいつでも省略可能(スキップしても
  そのまま合戦は始まる)
- 全ユニットが行動し終わるか「ターン終了」をタップすると敵軍フェイズに移る
- **勝利条件は「敵を全滅させること」ではなく「撤退地点(黄色いマス)まで撤退すること」**。
  信長が撤退地点に到達すると即座に決着がつく
  - 信長を含む4名以上が撤退できれば「完全勝利」
  - 信長は撤退できたが3名以下しか生還できなければ「辛勝」
  - 信長が討死、または15ターン以内に撤退できなければ敗北

## 世界観・登場武将

1570年、越前朝倉氏を攻めていた織田信長軍だったが、同盟関係にあった浅井長政の
裏切りにより挟撃の危機に陥る(世に言う「金ヶ崎の退き口」)。プレイヤーは織田軍を
指揮し、敵軍に包囲される前に撤退地点まで軍を退かせる。

- **織田軍**: 織田信長(総大将・高攻撃・「天下布武」で自身の攻撃力を一時強化)、
  木下藤吉郎(足軽大将・高移動力・「殿軍」でHP半分以下になると防御力上昇)、
  徳川家康(援軍大将・高防御・隣接する味方の防御力を上げる)、池田勝正(先鋒・
  複数の敵に囲まれると攻撃力上昇)、明智光秀(鉄砲大将・唯一2マス先から攻撃できる
  遠距離ユニット)、松永久秀(謀将・「攪乱」で敵1体の攻撃力を一時低下させる)、
  朽木元綱(道案内・街道と山地の移動コストが下がる)
- **朝倉・浅井軍**: 朝倉義景・朝倉景恒・朝倉兵(初期配置)、浅井長政・浅井兵
  (4ターン目に東側の山地から裏切りの援軍として合流)

## 仕組みメモ

- 判定ロジックはDOM/Canvasから独立した純粋関数にしている
  - `computeMoveRange` — 地形移動コストを考慮したダイクストラ法による移動可能範囲計算。
    味方ユニットは通り抜けられるが停止はできず、敵ユニットは通行そのものを阻む
  - `computeAttackableTargets` — 各移動先マスから、ユニットの射程(通常1、光秀のみ2)
    内に入る敵を判定
  - `computeHitChance` / `computeDamagePreview` / `computeKillChance` — 命中率・
    予想ダメージ・撃破確率の算出。地形の回避/防御補正、レベル差、特殊能力による
    攻撃力/防御力修正をすべて考慮する
  - `applyExp` — ダメージ量・撃破に応じた経験値付与とレベルアップ処理
  - `checkOutcome` — 信長の生死・撤退状況・ターン経過から勝敗を判定
  - `pickEnemyAction` — 射程内に自軍ユニットがいれば最もHPの低い相手を攻撃、
    いなければ最も近い自軍ユニットへ接近する、というシンプルな敵AI
- 池田勝正の「複数の敵に囲まれると攻撃力上昇」、家康の「隣接する味方の防御力上昇」、
  藤吉郎の「HP半分以下で防御力上昇」は、戦闘計算時に周囲のユニット配置を見て
  動的に加算される仕組みにしている
- マップは12列×16行のグリッドをASCIIアートの文字列配列(`MAP_ROWS`)で表現し、
  文字→地形種別へのマッピングで読み込む方式にしている。北(盤面上部)が
  金ヶ崎城のある越前側、南(下部)が撤退地点という縦長の回廊状マップにすることで、
  「奥から手前へ退却する」という進行方向がスマホの縦持ち画面と自然に一致するようにした
- カメラは選択中ユニット(未選択時は信長)を縦方向に追従する(横方向はグリッド幅が
  画面幅にちょうど収まるためスクロール不要)
- 出陣時の会話デモは、SRPGでよくある「左右に肖像を並べ、発言していない側は
  暗く沈める」演出を素のDOM(`<img>`+CSS)で実装している。肖像は全て右向きの
  1枚絵素材(`assets/portraits/`)なので、左側に立つキャラは無変形のまま
  (自然に右=中央を向く)、右側に立つ信長だけ`transform: scaleX(-1)`で
  左右反転して中央(=左)を向かせている。信長は全ての掛け合いに登場するため
  右側に固定し、話し相手側(家康→光秀→池田勝正→家康→藤吉郎)だけを
  左側で差し替える構成にした

## テスト

- ユニットテスト: マップ地形の生成・地形補正値・命中率/ダメージ/撃破確率の計算式・
  経験値とレベルアップ・その他純粋関数
- 移動範囲/射程テスト: ダイクストラ法による移動範囲計算(味方すり抜け・敵ブロック・
  朽木の地形割引が実際に到達可能マスを変えることを実測で検証)、射程による
  攻撃対象判定(近接/遠距離の差異)
- ゲームフロー統合テスト: ユニット選択→移動→攻撃→戦闘解決→ターン終了→敵AIフェイズ→
  次ターン、4ターン目の裏切り援軍出現、信長撃破/撤退/ターン超過それぞれの勝敗判定を検証
- 実タッチ入力テスト: 実際のタップ座標からユニット選択・移動・行動メニュー操作・
  ターン終了までの一連の操作を検証
- 会話デモテスト: 全33行を実タップで進めた際の発言者・肖像の左右差し替え・
  ハイライト/暗転の切り替え・ナレーション行(「――その時。」等、肖像非表示)・
  スキップボタン(タップ判定が下の行に伝播しないこと)を検証。デモ終了後に
  合戦が正しく開始されること、スキップ時も同様に開始されることを確認
- 長時間プレイテスト: 全ユニットが毎ターン待機するだけの15ターン超プレイと、
  「南へ急ぐ」実戦略での撤退成功まで、それぞれ実際のゲーム操作のみで完走することを
  確認(タイムアウト負け/部分勝利がそれぞれ意図通り発生することも確認)
- `window.__debug` フックは最終コミット前に削除済み(`grep -n "__debug"` で該当なしを確認)
