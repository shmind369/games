# FALL FORWARD

「『足を出して前に進むゲーム』ではなく、『前に倒れた結果として足が出て、
その足が地面に着いたことで初めて前進するゲーム』を作ってほしい」という
企画書をもとに、新規ファイルとして立ち上げたプロトタイプです。

プレイヤーが操作するのは「いつ足を出すか」(画面タップ)だけ。
キャラクターは常に一定の速さで前へ倒れ続けており、タップした瞬間の
傾き具合によって進む距離が変わります。早すぎるタップでは少ししか
進めず、倒れ切る直前のギリギリのタップほど大きく進みます。タップが
間に合わなければ転倒してゲームオーバーです。ゴールまでのタイムを
競うタイムアタック形式にしています。

企画書で最も重視されていたのは「ゲームの核を崩さないこと」、つまり
「タップしたら前進するゲーム」にしないことでした。そのため、
「時間経過で傾きが増える→タップで足を出す→着地して初めて前進し、
姿勢が立て直される(傾き0に戻る)」という一連の因果関係をそのまま
ゲームロジックの構造にしており、タップ自体は移動のトリガーではなく
「足を出す」という行為そのものとして実装しています。

スマートフォン縦画面専用の試作です(PC操作は想定していません)。
段差・坂などの地形バリエーション、複数ステージ、連続コンボ演出など、
企画書で明示的に要求されていない要素は追加せず、まずは核となる
「倒れる→ギリギリで足を出す→進む」というゲームループ1本に絞って
実装しています。

Three.js製。既存の他プロジェクトのコードは一切参照・流用しておらず
(`vendor/three.module.min.js`は他プロジェクトと同じ第三者ライブラリの
同一revision(r160)をコピーしたものです)、アプリ本体のロジック・
描画はすべてこのプロジェクト用に新規に書き下ろしています。

## 遊び方

`index.html` をブラウザで開くか、ローカルサーバーで配信してください。

```bash
cd games/fall-forward-3d
python3 -m http.server 8080
# http://localhost:8080 を開く(スマートフォンの縦画面を想定)
```

- **タップでスタート**: 画面中央のボタンを押すとタイマーが始まり、
  キャラクターが前へ倒れ始める
- **画面をタップ**: 足を出す。タップした瞬間の傾き具合によって
  進む距離が変わる
  - 早すぎる(傾きが小さい): 少ししか進まない
  - ギリギリ(傾きが限界に近い): 大きく進む
  - 間に合わない(傾きが限界を超える): 転倒してゲームオーバー
- 画面左下の「傾き」メーターが、現在の転倒危険度を色(緑→黄→赤)で
  示す。満タン(赤)になる前にタップできなければ転倒する
- 画面上部のバーはゴールまでの進行度、数字はタイマー
- ゴールまで到達すると「ゴール！」とタイムが表示され、過去のベスト
  タイムより速ければBESTが更新される
- 転倒・ゴールのどちらでも「もう一度」で最初からやり直せる

## 仕組みメモ

### ゲームロジック(Three.js非依存の純粋関数)

企画書の核となる因果関係を、Three.js・DOMに依存しない純粋な関数として
実装している(`third-person-boxer-3d`のclassifySwipe等と同じ考え方だが、
このプロジェクト用に独立して書いている)。

```js
function advanceTime(state, dtSeconds) {
  // 時間経過で傾き(leanDeg)が増えていく。限界角度(MAX_LEAN_DEG)に
  // 達すると転倒(gameOver)する
}
function computeStepResult(leanDeg) {
  // 「今この傾きでタップしたら何m進むか」を計算する。
  // 傾き/限界角度の比を2乗したカーブを使っており、倒れ切る直前ほど
  // 進む距離が急激に伸びる(=「早すぎてもダメ、ギリギリが一番伸びる」
  // という企画書のゲーム性そのもの)
}
function tapStep(state) {
  // タップ=足を出す。進んだ距離を加算し、傾きを0に戻す(着地して
  // 姿勢を立て直す)。ゴール距離に到達すればクリアにする
}
```

この3つの関数だけで「早すぎてもダメ、遅すぎてもダメ、ギリギリが
一番速い」というゲーム性の核が成立しており、実際にPlaywrightから
これらの関数を直接呼び出すことで、見た目のアニメーションを待たずに
タイミングのシビアさを決定論的に検証できる(後述のテスト参照)。

### レンダーループは実時間、ロジックテストは時間を止めて検証

`render()`はrequestAnimationFrameで実時間の`dt`を使い続けて
`advanceTime`を呼ぶ(実際のプレイ体験として自然な挙動)。その一方で、
自動テストでロジックだけを決定論的に検証したい場合のために、
`window.__game.setTestTimeFrozen(true)`でレンダーループ側の時間進行を
止め、`__advanceTimeRaw`/`__tapStepRaw`で直接時間を進めたり足を
出したりできるようにしている(見た目の描画自体は止まらない)。

### キャラクターの表現(支点を中心に前へ傾く、という核を一目で伝える)

詳細な関節モデルではなく、「今接地している足(支点)を中心に、身体が
前へ傾いていく」という核のルールが一目で伝わることを優先した簡易構成。

- `hipPivot`: 現在接地している足の位置(＝キャラクターの現在地)
- `bodyPivot`: `hipPivot`を支点に前方へ傾く胴体+頭(`leanDeg`をそのまま
  Z軸回転として反映するだけ)
- 軸足(白い線): `hipPivot`から胴体の付け根までを結ぶ
- 前足(黄色い線): 胴体の付け根から、**「今タップしたら着地する位置」**
  まで伸びる。`computeStepResult(leanDeg)`の結果をそのまま可視化して
  おり、傾くほど・ギリギリになるほどこの足が長く伸びる。これにより
  「このタイミングで出したらどれだけ進むか」が常に視覚的に予告される
  (企画書の「身体の傾きを視覚的に分かりやすくする」という要件に対応)
- 黄色いリング: 前足の着地予定地点の目印

ロジック上の位置(`state.distance`)と見た目の位置(`visualX`)・
見た目の傾き(`visualLeanDeg`)はあえて分離している。タップした瞬間
ロジックの傾きは即座に0になる(タイミング判定はフレーム単位で厳密で
あるべきため)が、見た目はそこへ指数的に補間して滑らかに戻すことで、
判定の正確さと見た目の自然さを両立させている。画面左下の傾きメーターは、
見た目ではなくロジック側の正確な値から描画しており、プレイヤーが
正確なタイミング判断に使える指標にしている。

### カメラ

サイドビュー固定。キャラクターの少し後ろ上空から、横から見る構図で
`visualX`に追従する(オービット操作はない。企画書の「サイドビュー
カメラでキャラクターを見る」という要件通り、視点操作自体をゲーム性に
含めていない)。

### ゴール判定とタイムアタック

`GOAL_DISTANCE`(40)に到達した時点で`cleared`になり、タイマーが
止まる。転倒(`gameOver`)はクリアしていないため、ベストタイム更新の
対象にはしていない。ベストタイムはこのブラウザタブを開いている間だけ
保持する(ページを再読み込みすると失われる。永続化は今回のスコープ
外とした)。

## テスト

Playwrightで以下を確認した。

**ゲームロジック(`setTestTimeFrozen(true)`で決定論的に検証)**

- 時間経過(`advanceTime`)で傾きが増えること、経過時間も進むこと
- 傾きが限界角度に達すると転倒(`gameOver`)し、`running`が`false`に
  なり、傾きが限界値でクランプされること
- 転倒後にタップしても距離が変化しない(無効化されている)こと
- `computeStepResult`が、傾きが小さいほど進む距離が小さく、限界に
  近いほどBASE_STEPに近い距離になること(早すぎ/ギリギリの差が
  実際に出ること)。傾き0でも最低限は進むこと
- タップ(`tapStep`)で実際に距離が増え、傾きが0にリセットされ、歩数が
  1増えること
- 限界ギリギリのタップを繰り返すとゴール距離に到達してクリアし、
  距離がちょうどgoalDistanceでクランプされ(超過しない)、`running`が
  `false`になること

**実際のUI操作(実時間・実タップ)**

- 初期状態でスタートオーバーレイが表示され、スタート前は画面タップ
  しても何も起きないこと
- スタートボタンでオーバーレイが消え、ゲームが始まること
- 実際の画面タップで距離が増え、タイマー・距離バーの表示が更新
  されること
- タップせず放置すると時間切れで転倒し、ゲームオーバー画面が
  自動的に表示されること(タップ経由のクリア/転倒だけでなく、
  時間経過だけで転倒するケースも同じ処理で検知できることの確認)
- ゲームオーバー中の画面タップが無視されること
- 「もう一度」でゲームオーバー画面が消え、スタート画面に戻り、
  距離・経過時間・転倒状態がリセットされること
- タップを続けてゴールするとクリア画面が表示され、ベストタイムが
  記録・表示されること
- クリア後に「もう一度」しても、ベストタイムは保持されたまま
  ゲーム状態だけがリセットされること
- 画面の向き(縦/横)を変えてもエラーなく描画・操作が継続できること

いずれもコンソールエラーなし(favicon 404を除く)で成功している。

## 今後について

企画書にある以下の要素は、「まず核となるゲームループを崩さずに成立
させる」ことを優先し、今回は意図的に実装していない。

- 段差・坂などの地形バリエーション(現在は平坦なコースのみ)
- 複数ステージ・ステージセレクト
- ベストタイムの永続化(現在はタブを開いている間のみ保持。
  `localStorage`等での保存は今後の拡張として考えられる)
- 連続して上手く足を出し続けた際のコンボ演出・加点
- 詳細な関節アニメーション(現在は支点を中心に傾く簡易表現のみ)
