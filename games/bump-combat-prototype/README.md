# 体当たり戦闘プロトタイプ

初期の「イース」シリーズにあった体当たり戦闘(攻撃ボタンなし、敵にぶつかって戦う)を、
スマホ縦持ち・片手操作でどこまで気持ちよく再現できるかを検証するための実験用プロトタイプです。
Three.js等の外部ライブラリは使わず、素の2D Canvasで実装しています。

**目的は操作感の検証のみ**です。見た目・演出・スコア・アイテム・レベル・BGMは意図的に
実装していません(詳細は下記「スコープ外」を参照)。

## 遊び方

`index.html` をブラウザで開くか、ローカルサーバーで配信してください。

```bash
cd games/bump-combat-prototype
python3 -m http.server 8080
# http://localhost:8080 を開く
```

- **画面のどこでもスワイプ**した方向(東西南北の4方向に補正)へプレイヤーが移動
- 指を動かしている間だけ移動し続け、離すと停止。指を離さずに方向を変えることも可能
- 移動中は向いている方向(上下左右)に応じた歩行アニメーションが再生される
- 攻撃ボタンはなし。**敵(赤い四角)へ接触すると自動で戦闘が発生**
- 敵は放っておくとゆっくりプレイヤーに近づいてくる。敵の追跡も斜め移動なし
  (1フレームごとにX軸・Y軸どちらか差が大きい方だけを移動する)

## 戦闘判定(イース風オフセット判定)

移動方向の軸に対して**まっすぐ正面から**敵にぶつかるとプレイヤーがダメージを受け、
**中心を外して(横にズラして)**接触すると敵を撃破します。具体的には:

- 左右方向に移動中の接触 → 縦方向のズレが一定以上あれば撃破、なければ被弾
- 上下方向に移動中の接触 → 横方向のズレが一定以上あれば撃破、なければ被弾

敵のHPは1で、撃破すると即座に消滅します。プレイヤーのHPが0になるとゲームオーバー
(タップで再挑戦)。

## 仕組みメモ

- 当たり判定の勝敗ロジック(`resolveContact`)はDOM/描画から独立した純粋関数にしており、
  座標と向きを直接渡して単体テストできる構造にしている
- 同じ接触が続くフレームごとに何度も判定されないよう、「重なり始めた瞬間」だけ判定する
  エッジトリガー方式にしている(重なったまま何フレームも連続ダメージ/連続撃破にならない)
- スワイプ方向は、指を置いた位置から現在位置までのベクトルを毎フレーム再計算しており、
  指を離さずに方向転換できる
- 歩行アニメーションは経過時間ではなく**実際に移動した距離**でアニメーションの位相を進めており、
  立ち止まった瞬間に足の動きも止まる(歩幅と足の動きがずれない)
- プレイヤーの見た目は `assets/player-walk.png`(4方向×4フレームのスプライトシート、フリー素材)を使用。
  「右向き」だけは専用素材がないため、「左向き」を`ctx.scale(-1, 1)`で左右反転して代用している
