# MIDNIGHT ROOFTOP 3D

「1986年のMSXゲーム『ミッドナイトブラザーズ』のような、ビル内を1人称視点の3D迷路で
探索し、アイテムを集めて屋上へ脱出するゲームを作ってみたい」というご相談から生まれた
オリジナル作品です。キャラクター・ストーリー・グラフィック・タイトルは元のゲームとは
一切関係のない、この題材にインスパイアされたオリジナルの内容にしています。

深夜のオフィスビルに侵入し、館内に隠された合鍵をすべて集めて、屋上への扉を開けて
脱出するのが目的です。Three.js製、一人称視点のグリッドベース3D迷路。

## 遊び方

`index.html` をブラウザで開くか、ローカルサーバーで配信してください。

```bash
cd games/midnight-rooftop-3d
python3 -m http.server 8080
# http://localhost:8080 を開く
```

- **▲/▼** で前進・後退(後退は振り向かず、そのまま後ろに下がる)
- **◀/▶** でその場旋回
- 壁の中には怪しい場所が隠れていることがある――近づいて向き合うと
  画面右下に「調べる」ボタンが現れる。タップすると隠し通路を発見できる
- 合鍵をすべて集めると屋上への扉(2階の光る扉)が開き、そこへ進むとクリア

## 実装メモ

判定ロジックは`maze.js`にDOM/Three.js非依存の純粋関数としてまとめている
(Node上で直接ユニットテスト可能)。

- `parseFloor` — ASCIIアートのフロアマップ(1行1文字)を解析してグリッド化
- `attemptMove(state, floors, stepHeading)` — 前進・後退の共通実装。
  `stepHeading`を省略すると現在の向きへ前進、`(heading+2)%4`を渡すと
  向きを変えずに後退する。壁への衝突・アイテム取得・階段による階層移動・
  屋上への扉(鍵が足りなければブロックしてメッセージを返す)をすべて
  この1関数で処理する
- `facingSecret` / `attemptSearch` — 一見普通の壁と区別がつかない
  `SECRET`タイルを、プレイヤーが隣接して向き合っているときだけ
  「調べる」ボタンで発見できるようにする仕組み
- 見た目は完全に他の壁と同じにしてあり、「調べるボタンが出た」という
  UI上の手がかりだけが唯一のヒントになっている

## マップ設計で見つかった問題

館内は2フロア(1F・2F)のASCIIアートマップで構成しており、2Fには
「調べる」で見つかる隠し部屋(合鍵1本)を配置している。実装中、この隠し部屋への
唯一の経路が2Fの入り口(1Fからの階段を上がった直後の位置)を再度踏むルート
しかないという設計ミスが発覚した。入り口のマスは「階段」タイルなので、
再度踏むと1Fへ引き戻されてしまい、隠し部屋を訪れた後に2Fの他のエリアへ
進めなくなる(1Fへ強制送還→階段を上り直す、という遠回りしかできない)という
問題があった。マップに別ルート(横穴)を追加し、階段を再度踏まずに
隠し部屋とフロアの他エリアを行き来できるよう修正した。この問題は
Node上のユニットテスト(「階段を踏まずに全アイテム・扉へ到達できるか」を
BFSで検証)で機械的に検出できるようにしてある。

## 今回の設計判断(元ネタとの違い)

- 元のゲームは2人同時プレイ(画面分割)だったが、今回はスマートフォン1台での
  プレイを前提に1人用にしている
- 操作は方向キーではなく、画面下部の十字ボタン(タップ)にしている
- 敵・時間制限は導入していない(元のゲームも「理不尽な罠のない」設計哲学
  だったとのことなので、まずは探索とアイテム収集・隠し通路探しに絞った
  最小構成にしている)

## テスト

- `maze.js`の純粋関数をNode上で直接ユニットテスト(フロア解析・移動・
  壁衝突・後退移動・アイテム取得・階段による階層移動・隠し壁の発見・
  屋上への扉のロック/解錠・全アイテムと扉への到達可能性のBFS検証など)
- Playwrightで実際にゲームをプレイし、1Fの2つのアイテム取得→階段で2Fへ→
  隠し壁の発見→隠し部屋のアイテム取得→残りのアイテム取得→屋上への扉を
  開けてクリア、という完全な一連の流れをエンドツーエンドで検証
- 実タップでの十字ボタン操作(前進・後退・旋回)・スタートボタン・
  縦画面固定(横向き時の回転案内)を検証
- `window.__debug`フックは最終コミット前に削除済み
