# CARD CANVAS

「メモ、タスク、アイデア、買い物、写真、記録など、何のために使うか最初から
決めない、自由なカードアプリ」という企画書に基づいた2Dプロトタイプです。
用途を限定せず、カードを置く・眺める・動かす・重ねる・処理する、という
行為そのものが心地よいことを目指しています。3D空間や物理演算は使わず、
DOM要素とCSSトランジションだけでカードの質感・動きを表現しています。

「未処理◯件」のような急かす表現、派手なパーティクルや効果音、自動で
カードが動くような演出はあえて入れていません。触ったときにだけ反応する、
静かなアプリです。

## 遊び方

`index.html` をブラウザで開くか、ローカルサーバーで配信してください。

```bash
cd games/card-canvas
python3 -m http.server 8080
# http://localhost:8080 を開く
```

- 右下の **＋** ボタンでカードを1枚追加する(タイトル・本文は空のまま、
  ふわっと小さく現れて自然な大きさに落ち着く)
- カードを指でつかんで自由な位置に**ドラッグ**できる。つかんだ瞬間わずかに
  浮き上がり、指に追従し、離すと軽く沈んで落ち着く
- カードを**軽くタップ**すると、タイトル・本文・色を編集するシートが
  下からせり上がる。何も触らず閉じても構わない
- カード同士は重ねられる。最後に触ったカードが一番上に来る
- 編集シートの「削除」でカードを片付けられる(ふわっとフェードアウトする)
- データは`localStorage`に自動保存される。ページを閉じても、
  再度開けば同じ配置・内容のまま再開できる

## 仕組みメモ

カードのデータモデル・位置のクランプ・タップ/ドラッグの判別・
`localStorage`の読み書きは`cards.js`にDOM非依存の純粋関数としてまとめている
(Node上で直接ユニットテスト可能)。

- **タップ/ドラッグの判別**: `pointerdown`から`pointerup`までの総移動距離と
  経過時間だけで判定する(`classifyPointerGesture`)。指を置いてから
  ごくわずか(4px)動いた時点で「確定ドラッグ」とみなして持ち上げアニメーション
  (`.dragging`クラス)を付け、それ未満のまま素早く離せばタップ=編集シートを開く、
  という単純な仕組みにしている。ドラッグ中は指の移動量をそのままカードの
  位置に反映するので、操作に遅延を感じさせない
- **アニメーションの方針**: カードの基本状態には`cubic-bezier(0.22, 1.1, 0.4, 1)`
  という、ごくわずかにオーバーシュートしてから収まる緩やかなイージングを
  使い、「ぽすっ」と落ち着く感触を狙っている。企画書が明示的に避けたいと
  していた「激しいバウンド」「過剰な弾性」にならないよう、オーバーシュート量は
  最小限に抑えた。ドラッグ中(`.dragging`)だけは追従を優先して短い
  トランジションに切り替え、指を離した瞬間にこの緩やかなイージングへ戻す
- **重なり順**: 各カードは`zIndex`を持ち、タップ・ドラッグ開始のどちらでも
  「現在の最大値+1」を割り当てて最前面に上げる(`bringToFront`)。特別な
  スタック構造は使わず、フラットな配列とzIndexだけで前後関係を表現している
- **位置のクランプ**: このプロトタイプには無限キャンバスやスクロールがなく、
  画面外に出たカードは事実上失われてしまうため、`clampPosition`で
  ドラッグ中・追加時ともに画面内に収まるよう制限している
- **保存**: 追加・編集・削除・ドラッグ終了のたびに、カード配列全体を
  JSON化して`localStorage`に書き込む(`parseCards`/`serializeCards`)。
  ドラッグ中は毎フレーム保存せず、指を離した瞬間だけ保存することで
  無駄な書き込みを避けている。読み込み時は壊れた・想定外の形式のデータでも
  クラッシュせず、安全な既定値に落として空のボードとして復帰する
- **見た目**: カードはCanvasではなく通常のDOM要素(`<div>`)として描画して
  いる。タイトル入力・本文入力といったテキスト編集が必要なアプリなので、
  Canvas上に独自のテキスト入力を実装するより、ネイティブの`<input>`/
  `<textarea>`を使えるDOM構成の方がシンプルで扱いやすいと判断した

## テスト

- `cards.js`の純粋関数をNode上でユニットテスト(カード生成の既定値・
  位置のクランプ・zIndexの採番/繰り上げ・カードの更新/削除・
  タップ/ドラッグの判別閾値・`localStorage`データの読み書きと
  破損データに対する安全なフォールバック)
- Playwrightで実際のポインタ操作を再現し、＋ボタンの実タップでの
  カード追加(空のまま追加され、編集シートは強制的に開かないこと)、
  カードへの実タップでの編集シート表示・タイトル/本文の保存・
  カード表面への即時反映を検証
- 実ドラッグでのカード移動(移動量が正しく反映されること、ドラッグは
  編集シートを開かないこと、`.dragging`クラスが操作中だけ付くこと、
  最前面に上がること)、画面外への大きなドラッグが画面内にクランプ
  されることを検証
- 編集シートからの削除で該当カードだけがデータ・DOM双方から消えること、
  ページのリロードを挟んでもカードの配置・内容が保持されることを確認
- 2枚のカードがほぼ重なって追加される(ジッターの範囲が小さいため)ことを
  実際に確認し、テストでは重なりの影響を考慮して上のカードを先に
  どかしてから個々のカードを操作するようにしている
- ページエラー無しの最終スモークテストを実施
- `window.__debug`フックは最終コミット前に削除済み(`grep -n "__debug"`
  で該当なしを確認)
