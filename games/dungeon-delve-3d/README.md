# DUNGEON DELVE 3D

「『ダンジョンマスター』のようなグリッドベース・リアルタイムの1人称ダンジョン
探索に、ローグライクの手続き生成とパーマデスを組み合わせたい」というご相談から
生まれたオリジナル作品です。システムの着想を得てはいますが、ダンジョン構成・
モンスター・アイテム・タイトルは元のゲームとは一切関係のない、この題材に
インスパイアされたオリジナルの内容にしています。

パーティ編成や呪文システムは省き、たった1人でダンジョンに潜って武器を振るう
シンプルな近接戦闘だけに絞った、ライト級の「ダンジョンマスター風ローグライク」
です。ダンジョンは毎回手続き生成され、地下5階への到達がクリア条件。倒れたら
そこで終わり(パーマデス)、次はまた新しいダンジョンから挑むことになります。

## 遊び方

`index.html` をブラウザで開くか、ローカルサーバーで配信してください。

```bash
cd games/dungeon-delve-3d
python3 -m http.server 8080
# http://localhost:8080 を開く
```

- 画面を**上スワイプ**で前進(壁のスイッチがあれば移動の代わりに操作する)、
  **下スワイプ**で後退、**左右スワイプ**でその場90°旋回(東西南北の4方向移動)。
  左右にスワイプしたまま指を止めるとその方向へ**カニ歩き**(旋回とは判定を
  分離しており、一定時間(160ms)以上保持されて初めてカニ歩きに切り替わる
  ので、サッと払う旋回と同時発火することはない)
- **「たたく」** ボタンで正面のマスにいるモンスターを攻撃する(振り自体は
  素早いが、武器ごとに次の一撃までの硬直=クールダウンが長い)。ボタン内の
  ゲージが満タンのときだけ攻撃でき、攻撃するとゲージが0%に戻って再び満タン
  になるまで連打しても発動しない
- モンスターはリアルタイムで動き、正面だけでなく横・後ろからも隣接すれば
  攻撃してくる。ただし隣接した瞬間には攻撃せず、一拍(`attackInterval`分)
  溜めてから初撃を放つ――その間に離れれば攻撃はキャンセルされる。攻撃できる
  のは自分が向いている方向のモンスターだけなので、複数に囲まれたら旋回して
  各個撃破する必要がある
- 地下3階以降には**ドッペルゲンガー**が1階につき最大1体出現する。一見ただの
  冒険者そのものの姿(帽子・ジャケット・ジーンズの実在するボクセルモデル)を
  しているが、正体は化け物――スケルトンより硬く、オーガほどではない中堅の
  強敵
- 床に落ちているポーションで回復、武器を拾うと自動で装備が切り替わる
- 部屋と通路の境界には必ずシャッター式の扉があり、最初は閉まっている。
  **扉のマスをタップすると開閉する**(独立したボタンはなく、扉そのものが
  操作ポイント)。開くときは「ガラガラガラッ……!」と巻き上がり、閉じる
  ときは最後にずしりと着地する「ガラガラガラッ……ガシャン!」の動き――
  完全に上へ収納されるまでは通行不可で、プレイヤーもモンスターも通れない。
  効果音も動きに合わせて鳴る(開閉のガラガラという擦過音、閉まる瞬間の
  重い衝撃音、施錠時の拒否音、鍵を使った時の解錠音)。開いている扉の
  マスにモンスターがいる状態で扉を閉じると、挟み込みで環境ダメージを
  与えられる(通常攻撃とは別枠のダメージ)。1つ隣のマスにいる扉しか
  操作できない
- 隠し宝物庫の扉は**鍵付き**で、対応する鍵を拾うまでは開かない(タップしても
  「鍵が必要だ…」と表示されるだけ)。鍵は必ず、その鍵付き扉を通らずに行ける
  場所に配置されるので、鍵を探せずに詰むことはない。鍵付き扉は通常の扉と
  違う色合い(鈍く冷たい金属色)で見分けられる
- 階段まで到達すると次の階へ。地下5階に到達すればクリア
- HPが0になったら力尽きてゲームオーバー。ダンジョンは次回また新しく生成される
- モンスターは待機中も弾んだり縮んだりする簡単なアニメーションで動いている
  (個体ごとにアニメーションの位相をずらしているので複数体が同時にバウンド
  しない)
- 画面左上に常時ミニマップを表示。『トルネコの大冒険』のような塗り潰し型
  で、歩いたことのある場所しか見えない――通路は実際に足を踏み入れたマス
  だけが1マスずつ開示されるが、部屋は足を踏み入れた瞬間に部屋全体の形が
  一度に開示される。プレイヤーは向いている方角を示す黄色い三角形、
  モンスターは赤い四角(自分がいる部屋の中にいる個体だけ、通路にいる間は
  隣接1マス以内の個体だけを表示――曲がり角の先や通路の奥に何がいるかは
  見えない)、アイテムは部屋に入ると表示される水色の四角、階段は水色の
  輪郭のみの四角。扉は茶色(鍵付きは金色)で、開いている扉は塗りつぶしで
  はなく輪郭だけになり、通行可能かどうかが一目でわかる

## 実装メモ

判定・生成ロジックは`dungeon.js`にDOM/Three.js非依存の純粋関数としてまとめている
(Node上で直接ユニットテスト可能)。`main.js`はThree.jsでの描画とリアルタイム
ループ(モンスターAIのtick、攻撃の解決、カメラ・メッシュの補間)を担当する。

- `generateFloor(floorNumber, rng)` — 3〜5個の矩形の部屋を、部屋数に応じた
  升目状のセクター(1セクターにつき1部屋、セクター間に1マスの余白)へ
  ランダム配置してから、シャッフルした順番でL字型の通路(`carveCorridorPath`)
  で1本ずつ繋いでいく(`carveRooms`)。セクター単位で配置するため部屋同士が
  重なったり隙間なくくっついたりすることがなく、常に指定した部屋数を確保
  できる。各通路が部屋の外郭を横切る地点(`boundaryDoorCells`)に扉を1枚
  ずつ設置する。スタート地点からBFSで最も遠い床マスに階段を配置。
  モンスター・アイテムは残りの床マスからランダムに配置する(アイテムは
  部屋のマスのみ、ミニマップの「部屋に入ると表示」ルールと辻褄が合う
  ように)
- `HEADING_DELTA`(東西南北4方向)/ `isBlockingTile` — 移動・視界の可否を
  タイル種別(壁・ドア)と、ドアなら`state`が`"open"`かどうかで判定する
  共通ロジック。生成時のレイアウト判定(階段配置やモンスター湧き距離の
  計算)だけは`isStructurallyBlocking`という別の判定関数を使い、扉は
  常に通行可能とみなす――扉はデフォルトで閉まっているが、いずれ必ず
  開けられるので、生成ロジックが「本当の」迷路の形を見誤らないように
  分けている
- `toggleDoor(floor, player, x, y, now)` / `updateDoors(floor, now)` — 扉の
  状態機械(`closed`→`opening`→`open`→`closing`→`closed`、鍵付きなら
  `locked`)。タップ操作は`toggleDoor`を1回呼ぶだけの離散アクションで、
  開閉アニメーションの経過は`updateDoors`が`DOOR_ANIM_MS`(900ms)に基づき
  毎フレーム解決する。開いている扉のマスにモンスターがいる状態で閉める
  と、その場でモンスターに環境ダメージ(`DOOR_PINCH_DAMAGE`)を与える
- `placeVaultDoor` — 既存の通路や部屋には一切触れず、未使用の壁スペース
  だけを新しく掘って小さな宝物庫(部屋)と鍵付きドア1マスを作る。既存の
  到達性を壊しようがない構造なので、事後の解決可能性チェックが不要に
  なっている。対応する鍵アイテムは、この扉を通らずに行ける部屋のマスへ
  優先的に配置される(`generateFloor`側でポーションより先に確保)
- `main.js`の扉描画は「動くシャッター(`shutter`)」と「動かない枠・敷居
  (jamb/lintel/threshold)」を分けて構築し、それぞれのメッシュに
  `userData.doorId`を持たせている。タップ操作は`THREE.Raycaster`で
  画面座標からシーンへレイを飛ばし、最初にヒットしたオブジェクトの
  `doorId`を見て`toggleDoor`を呼ぶ(壁など扉以外に最初に当たった場合は
  何も起きない=扉越しの操作はできない)。開閉の見た目のタイミングは
  `dungeon.js`の`DOOR_ANIM_MS`と揃えてあり、開くときはイーズアウト、
  閉じるときは加速して最後にわずかに沈み込む「ガシャン」演出を計算式
  だけで表現している
- `roomIdGrid` / `floor.rooms` — 各マスがどの部屋に属するか(通路なら-1)を
  持つ配列と、部屋の矩形一覧。`floor.explored`(踏んだ通路マスの座標
  集合)・`floor.roomsEntered`(入った部屋idの集合)と合わせてミニマップの
  開示状態を表し、`revealAt(floor, x, y)`が移動のたびにこれを更新する
  (部屋マスなら部屋全体を、通路マスならそのマスだけを開示済みにする)
- `AGGRO_RADIUS` / モンスターの`awake`フラグ — スタート地点からこの距離より
  遠くにモンスターを配置し、索敵範囲に入るまで眠ったまま動かない。フロアに
  降りた瞬間に複数体へ同時に囲まれることがないようにするための仕組み
- `MIN_MONSTER_SPACING` — モンスターの湧き位置同士も一定距離空けることで、
  1体に近づいただけで隣の1体も一緒に起きてしまう「初手2対1」を避けている
- 攻撃・移動などの離散的なグリッド操作(`attemptMove`, `descend`など)は
  新しい状態オブジェクトを返すが、`stepMonsters`や`finishAttack`のような
  毎フレーム走るリアルタイム更新はパフォーマンスのため引数を直接書き換える
  ――というモジュール内の使い分けをコメントで明記している
- 壁・床・天井のテクスチャ、ゾンビのボクセルモデルは`main.js`側でCanvas/
  Three.jsのジオメトリから手続き的に生成しており、外部画像アセットには
  依存していない
- 扉の効果音も同じ方針でWeb Audio APIのオシレーター/ノイズバッファから
  その場で合成しており、外部音声ファイルには依存していない
  (`playDoorOpenSound`など)。ブラウザの自動再生制限に合わせて、
  `AudioContext`は最初のユーザー操作(スタートボタンやキャンバスの
  タップ)で`unlockAudio()`により解放される
- ドッペルゲンガーだけは唯一の外部アセット(`doppel.dae`)を使うモンスター。
  `collada-voxel.js`が、そのエクスポータ(Lindwurm Voxel Collada
  exporter)が吐く形式に絞った最小限のCOLLADAパーサーを実装しており、
  Three.js本体のColladaLoaderには依存していない。ボーンごとに頂点が1つ
  だけ(ウェイト分散のない「剛体」スキニング)という単純なリグなので、
  GPUスキニングは使わず、各頂点をバインド時点で所属ボーンのローカル座標
  へ一度だけ変換して小さなメッシュとして親子付けする方式で読み込む
  ――以降は通常のThree.jsのシーングラフ変換(`bone.rotation`など)を
  動かすだけで、Minecraft風の剛体アニメーションが素直に動く。
  Tポーズのバインド姿勢のままだと不自然なので、起動時に腕の骨
  (`LeftUpperArm`/`RightUpperArm`など)を回転させて自然な立ち姿に
  補正している。読み込みは起動時に一度だけ行い(`doppelReadyPromise`)、
  スポーンのたびに`cloneRiggedVoxel`でクローンする(メッシュはボーン
  ごとに元テンプレートと共有しつつ、マテリアルだけ複製することで、
  被弾フラッシュが他の個体に波及しないようにしている)
