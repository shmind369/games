# SLINGSHOT BOXING PROTOTYPE

「スマホ縦持ち専用・仮想パッド無し」のジェスチャー格闘ゲームのプロトタイプです。
任天堂の『パンチアウト!!』のようにプレイヤーと敵が正面から向かい合う形式ですが、
攻撃・回避・ガードのすべてを、画面上のボタンを一切使わずタッチジェスチャーだけで
行うことが最大の特徴です。攻撃はスリングショットのように「引く→溜める→離す」
という操作で繰り出します。キャラクター・演出は、この操作感を検証するための
プロトタイプとして、簡易的な図形で表現しています。

## 遊び方

`index.html` をブラウザで開くか、ローカルサーバーで配信してください。

```bash
cd games/slingshot-boxing-prototype
python3 -m http.server 8080
# http://localhost:8080 を開く
```

画面上に固定のボタンは一切ありません。すべてタッチジェスチャーで操作します。

- **パンチ**: 画面の左右どちらかを押さえ、外側(左半分なら左、右半分なら右)へ
  引いて溜め、指を離すと発動する。左は素早いジャブ、右は威力の高いストレート。
  引く距離と長さで威力・攻撃速度(隙の大きさ)が変わる
- **回避**: どこでもいいので素早く左右にスワイプする。敵の攻撃予備動作
  (腕が黄色く光って引かれる側)と逆方向に避けると成功
- **ガード**: どこでもいいので下にスワイプしたまま押さえ続ける。どちらの
  方向の攻撃も防げるが、押さえている間は他の操作ができない
- 敵の隙(攻撃直後の無防備な状態)にパンチを当てると通常より大きいダメージが入る

## 仕組みメモ

判定ロジックは`fight.js`にDOM/Canvas非依存の純粋関数としてまとめている
(Node上で直接ユニットテスト可能)。

- **ジェスチャーの判別**: パンチ・回避・ガードはすべて「指を置いた位置から
  どれだけ・どれくらいの速さで・どの方向に動かしたか」だけで区別している。
  ガードは押さえている間ずっと有効にする必要があるため、指を動かしている
  最中(pointermove)にリアルタイムで判定する。一方パンチと回避は、指を
  離した瞬間(pointerup)にまとめて判別する。「短時間で素早く動かした」場合は
  回避、「タッチした半分側から外側へ、それなりの距離・時間をかけて引いた」
  場合はパンチ、それ以外(引く方向が違う、動きが小さすぎる等)は何も
  起きない仮仕様にして誤入力を減らしている
- **パンチの威力**: 引いた距離を最大溜め距離で正規化した値(0〜1)に、
  押さえていた時間に応じた小さなボーナスを加えたものを「威力」とし、
  ダメージ量・攻撃の隙(発生の遅さ)の両方に反映している。引く動作から
  発射までの物理的な対応関係は、sling-battle-3dの「引いた距離→発射速度」の
  考え方を踏襲している
- **敵の行動**: idle(待機)→telegraph(予備動作。左右どちらかの腕を
  引いて色を変え、攻撃を予告する)→recovery(攻撃後の隙。この間に受けた
  パンチはクリーンヒット判定でダメージ増加)→idleのサイクルを繰り返す。
  telegraphの時間は、敵のHPが減るほど短くなる(体力が減るほど攻撃が
  速く・鋭くなる)。同じ側への攻撃が3回続きそうになると強制的に逆側へ
  切り替える、という調整もcounter-punch-3dの敵AIから踏襲している
- **被弾判定**: telegraph中にプレイヤーがガードしているか、正しい方向へ
  回避していれば「防御成功」フラグを立てておき、telegraphの時間切れの
  瞬間にそのフラグを見てダメージの有無を決める。プレイヤーは同時に
  1本の指しか使わない前提(マルチタッチ非対応)なので、パンチを
  溜めている最中は同時に回避・ガードができない――これによって
  「強いパンチを溜めている間は無防備になる」というリスクが、
  特別な仕組みを足さなくても自然に発生するようにしている
- 見た目は前面向きの敵キャラ(円+角丸四角形)と、画面下部に覗く
  プレイヤー自身のグローブ(円)だけで構成する、パンチアウト風の
  一人称視点を簡易的な図形で再現している

## テスト

- `fight.js`の純粋関数をNode上でユニットテスト(ジェスチャー判別の閾値・
  誤入力の除外・パンチ威力とダメージ/隙の計算・敵の状態遷移一巡・
  防御成功時の判定・ダメージ適用のクランプ・勝敗判定)
- Playwrightで実際のマウス操作によるドラッグ・スワイプを再現し、
  左右それぞれのパンチが正しい方向への引きでのみ発動すること(逆方向へ
  引いても何も起きないこと)、右ストレートが左ジャブよりダメージが
  大きいこと、素早い左右スワイプが正しい方向の敵攻撃だけを防ぎ
  逆方向では被弾すること、下スワイプ長押しでガードが有効になり
  離すと解除されることを検証
- 敵のHP・プレイヤーのHPをそれぞれ0まで追い込み、WIN/LOSEの結果画面が
  正しく表示されること、「もう一度」ボタンで両者フルHPの状態から
  やり直せることを実タップで確認
- 溜め中・敵の予備動作中・ガード中それぞれのスクリーンショットを撮り、
  3つの状態が見た目で明確に区別できることを確認
- ページエラー無しの最終スモークテストを実施
- `window.__debug`フックは最終コミット前に削除済み(`grep -n "__debug"`
  で該当なしを確認)

## スコープ外(意図的に未実装・今後の調整用)

- 敵の攻撃パターンの多様化(現状は左右どちらかの単発パンチのみ)
- 回避成功時の反撃ボーナスウィンドウなどの追加リターン
- サウンド・本格的なキャラクターアニメーション(円と四角形による
  仮の見た目に留めている)
- 複数ラウンド制・難易度調整(まずは1体・1本勝負で操作感の検証を優先)
