# SHIP IT SIM

HTML → CSS → JS → PHP と作り込んだWebサービスを、iOSアプリとしてリリースするまでの
開発工程を6つの短いミニゲームで駆け抜ける「開発工程ミニゲー集」です。
素の2D Canvasで実装しています(Three.js等は未使用)。

## 遊び方

`index.html` をブラウザで開くか、ローカルサーバーで配信してください。

```bash
cd games/ship-it-sim
python3 -m http.server 8080
# http://localhost:8080 を開く
```

「はじめる」をタップすると、以下の6工程を順番にプレイします。各工程は
20秒前後の短いミニゲームで、クリアすると★0〜3の評価がつき、次の工程へ進みます。
全工程クリア後は、獲得スター合計に応じた「初日ダウンロード数」「ストア評価」が
表示されます。

1. **HTML配置** — `header`/`nav`/`main`/`footer` のタグチップを正しいスロットへ
   ドラッグする
2. **CSSスタイリング** — 色相・サイズ・角丸の3本のスライダーを操作し、制限時間内に
   お手本と同じ見た目に合わせる
3. **JS配線** — 次々現れるコード行のうち、バグ(🐛)が付いているものだけをタップして
   直す。正常な行を誤ってタップするとミスになる
4. **PHPリクエスト仕分け** — 上から落ちてくるリクエストを、種類に応じて正しい
   バケツ(User/Order/Error)へドラッグする
5. **iOSアプリ化** — AppIcon/Splash/Info.plist/Build設定の4パーツを、工程1と同じ
   ドラッグ&ドロップの仕組みでXcodeプロジェクトに詰め込む
6. **審査対応** — 自動で進む審査バーの途中で届く指摘に、制限時間内にタップして
   素早く対応する。対応が遅れても失敗にはならず審査は進む(スコアが下がるのみ)

どの工程も「詰み」で進行不能になることはなく、多少手こずっても必ず次の工程へ
進めるようにしてあります(タイムアウト時は部分点で自動的にクリア扱いになる)。

## 仕組みメモ

- 判定ロジックはDOM/Canvasから独立した純粋関数にしている
  - `dragSlotHitTest` / `dragSlotFindSlot` — チップのヒット判定とドロップ先スロット判定
    (工程1「HTML配置」と工程5「iOSアプリ化」は、ラベル/アイコンだけ差し替えた
    同一の汎用ドラッグ&スロット・エンジンを再利用している)
  - `isCssMatched` / `cssMatchRatio` — お手本とのスタイル一致判定・近さの算出
  - `computeRoundScore` / `isCorrectBucket` — JS工程・PHP工程それぞれのラウンド採点
  - `shouldTriggerIssue` — 審査工程で指摘イベントを発火させるべきかどうかの判定
  - `starsFromRatio` / `starsFromMistakes` — 各工程共通のスター評価しきい値判定
  - `computeDownloads` / `computeRating` — 合計スターから最終結果画面の数値を算出
- 各工程のコンテンツ(お手本の色・バグの位置・リクエストの種類など)は
  シード固定の疑似乱数(mulberry32)で生成しており、同じシードなら毎回同じ内容になる
- 更新ループは各工程の `xxxStageUpdate(state, dt)` が `done` フラグを立てると、
  `checkStageCompletion()` が即座にクリア処理(結果記録・クリア画面表示)を行う。
  ドラッグ系工程はポインター操作の直後にも明示的にこの判定を呼んでおり、
  次のアニメーションフレームを待たずに確実にクリア扱いへ遷移する
